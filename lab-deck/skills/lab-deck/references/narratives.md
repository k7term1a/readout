# 報告敘事結構

導覽列就是故事線，讓聽眾隨時知道報告進行到哪裡。

- **單排**：章節本身就是故事線。名稱要短（2–4 字）、口語，**不要**直接使用論文章節名稱。
- **雙排**：章節用通用名稱（介紹／研究方法／實驗結果／結論），故事線放在子章節。
  子章節每章 2–5 個，名稱 2–6 字。

同一份簡報內，章節與子章節的名稱要固定。

## A. 單篇論文報告

### 單排版本

| 分頁 | 內容 | 常用頁型 |
|---|---|---|
| 問題背景 | 論文要解決的缺口，拆成 2–4 個問題，紅色標籤依序編號 | content（`kind: problem`） |
| 方法提案 | 先放一頁對照，再逐一說明每個解法，綠色標籤沿用相同編號 | mapping → content（`kind: solution`） |
| 實驗驗證 | 資料集與設定、主要結果、消融實驗；數字一律來自論文 | content（table / figs） |
| 討論啟發 | 對自己研究可借用什麼、有什麼限制或疑問 | split |
| 參考文獻 | 本篇＋報告中提到的相關論文，每筆一行摘要 | refs |

重點：
### 雙排版本（依使用者的論文報告範本）

| 章節 | 子章節 | 內容 |
|---|---|---|
| 介紹 | 領域背景 | 領域與任務分類；用漸進聚焦逐一帶過，並指定概念色 |
| | 過往研究 | 時間軸，再逐一畫出既有架構，每頁下方放紅色結論橫條（問題） |
| | 研究動機 | 問題 → 解法對照頁 |
| 研究方法 | 核心概念 | 沿用架構圖，用綠色描邊標出新加入的元件 |
| | 各方法元件（2–3 個） | 每個元件一個子章節，搭配論文圖的截圖標註 |
| | 任務推論 | 推論時的使用方式與優點 |
| 實驗結果 | 模型訓練 | 資料集與訓練設定 |
| | 各類實驗 | 依任務分類（沿用概念色）；表格截圖加紅框與說明 |
| | 質化分析、消融實驗 | 截圖標註 |
| 結論 | （可無） | 貢獻 → 效益、未來展望 |

### 兩種版本共通

- **問題與解法一一對應**是這種風格的骨幹。如果論文的貢獻無法對應到問題，就合併或改寫問題，讓每個紅色標籤都有對應的綠色標籤。
- 「討論啟發」是報告者自己的觀點，不是論文內容。報告者沒提供時，先草擬並在回報中標明「請確認」。

## B. 研究進度報告（自己的研究）

| 分頁 | 內容 |
|---|---|
| 問題背景 | 研究動機與要解決的限制（紅色標籤） |
| 概念提案 | 對應的解決概念（綠色標籤），加一頁對照 |
| 目前進度 | 已完成的實作與結果（藍色標籤），以圖為主 |
| 後續方向 | 尚未實作的部分、預計使用的資料、待確認事項；最後放一頁 split（應用 vs 限制） |
| 參考文獻 | |

分頁名稱可以依報告內容調整（例如「應用方向」、「後續方向」），但同一份簡報內要固定。

## C. 多篇論文導讀

- 每篇論文是一個分頁，名稱用簡稱（例如方法名稱或「第一作者＋年份」），不要用「所選論文」這種通用名稱，否則導覽列無法表達進度。
- 第一頁可用 split 或 mapping 說明這幾篇論文的共同問題；最後一頁用 refs 列出完整書目。
- 每篇論文內部依序講「問題 → 解法 → 結果」，各 2–4 頁。
- 用雙排導覽時，把「問題／方法／結果」設成每篇論文的子章節。

## 從 paper.json（ai-paper-annotator 產出）轉換

如果使用者有 ai-paper-annotator 產出的 `paper.json`，優先從它取材，不必重讀 PDF：

| paper.json | 用途 |
|---|---|
| `meta.title` / `venue` / `year` | 封面 `subtitle` 與 refs 第一筆 |
| `summary.problem_gap` + `fishbone.causes` | 問題背景的紅色標籤（每個 cause 類別可當一個問題） |
| `summary.contributions` | 方法提案的綠色標籤，並與問題配成 mapping |
| `summary.one_line` | 封面標題或方法頁的 `one_line` |
| `annotation.role == 方法提案 / 模型元件描述` 的段落 | 解法頁的 `full`，濃縮成 `short` |
| `annotation.role == 結果分析 / 消融實驗` 的段落 + `table_ref` | 實驗頁；數值從 `tables/table_X.json` 取，不自己估 |
| `figure` block（`id`、`caption_zh`） | `figs`，路徑為 `figures/<id>.png` |
| `summary.applications` | split 的「可以借用的」 |
| `evolutionary_path` | 可做成背景頁的圖，或放進 refs |

轉換時一律依本檔的故事線重新編排，不要把 paper.json 的 sections 直接當成分頁。
