# 2slide

一篇論文進來，產出兩種東西：

| 產出 | 給誰 | 做法 |
|---|---|---|
| **標注檔** | 自己讀 | 依 `2annotate` 的 SKILL.md 產出 paper.json、tables/、generate.py、style.css |
| **簡報** | 給別人聽 | 寫 deck.json，用 `scripts/build_deck.py` 渲染成 .pptx |

簡報是**初稿**：使用者拿到後會自己在 PowerPoint 裡修改。所以可編輯性比精緻度重要（見第 5 節）。

> **實作狀態**：`style.md` 描述的是目標風格，渲染器尚未全部支援。目前**尚未支援**：
> 原生架構圖、時間軸、漸進聚焦。遇到這些需求時，先用現有頁型近似呈現，
> 並在回報中說明。
> （每完成一項就從這段刪除，全部完成後刪掉整段。）

相關文件：
- `references/style.md`：兩種風格的視覺規範與配色系統。**做簡報前必讀。**
- `references/narratives.md`：故事線編排與 paper.json 對照表。**寫 deck.json 前必讀。**
- `references/spec.md`：deck.json 欄位與建置指令。
- `assets/example-deck.json`：完整範例。

## 1. 決定要產出什麼

| 使用者的說法 | 產出 |
|---|---|
| 只丟論文，或說「整理＋做簡報」「準備報告」 | 兩者都產 |
| 「只要批註」「整理這篇我自己看」 | 只產標注檔 |
| 「只要簡報」「直接做投影片」 | 只產簡報 |

沒講清楚就用預設（兩者都產），不要先停下來問。有做簡報時，還要確認下列三項，
使用者沒指定就用預設值，並在回報裡說明可以切換：

| 項目 | 選項 | 預設 |
|---|---|---|
| 導覽列 | `single`（單排）／`double`（雙排） | 論文報告用 `double`；研究提案、進度報告用 `single` |
| 密度 | `text`／`balanced`／`visual` | `single` 配 `balanced`、`double` 配 `visual` |
| 故事線 | 單篇論文／研究進度／多篇導讀 | 依素材判斷 |

## 2. 先做標注（兩者都產時）

先完整依 `2annotate` 的 SKILL.md 產出標注檔。簡報再從 **paper.json** 取材，不要重讀 PDF：
這樣兩份產出的內容、術語、圖表編號才會一致。

**只產簡報時**，仍在工作資料夾建立 paper.json 當中間檔（可以只寫 `meta`、`summary`、
主要段落與 `tables/`），但不交付 generate.py 和 style.css。

兩份產出共用同一個 `figures/` 資料夾與命名方式（`figures/figure_1.png`），使用者截一次圖兩邊都能用。

## 3. 寫 deck.json

- **故事線**：依 `references/narratives.md`。單排時，章節本身就是故事線；雙排時，章節用通用名稱，
  故事線放在子章節。
- **概念配色**：找出論文裡 2–3 組會反覆出現、需要區分的概念（例如「圖像層級／區域層級」
  「粗顆粒／細顆粒」），在頂層 `concepts` 各指定一個槽位，整份簡報固定不變。內文用 `{{概念}}` 標記，
  圖用 `figs[].concept`，表格列用第一格的 `{{概念}}`（見 `references/spec.md` 第 6 節）。規則見 `references/style.md`。
- **問題與解法成對**：每個問題都要有對應的解法，並加一頁對照。
- **三種文字都要寫**：每個內容頁都要有 `full`、`short`、`one_line`，之後切換密度就不必重寫。
- **標籤與標題都要寫**：每頁同時寫 `tag`（單排的「/ 彩色標籤」）和 `title`（雙排的黑字標題），之後切換導覽列就不必重寫。
- **一頁一個重點**：同一張圖要講好幾個重點時，用漸進聚焦拆成好幾頁，不要塞進同一頁。
- **不捏造數字**：數值只能來自論文或 `tables/*.json`；缺少的就寫「— 待填 —」。
- 「討論啟發」「結論」中屬於報告者個人觀點的部分，若是你草擬的，要在回報中標明請確認。

## 4. 建置與檢查

```bash
pip show python-pptx >/dev/null 2>&1 || pip install python-pptx   # 需要時加 --break-system-packages
python <skill-dir>/scripts/build_deck.py deck.json -o <name>.pptx
```

結論橫條預設是「點一下出現」的動畫；截圖標註加 `reveal: "click"` 也會依序點出。使用者要匯出 PDF、
上傳 Google 簡報，或說不要動畫時，加 `--keyframes`，每一下點擊拆成一頁。

截圖標註（`figs[].marks`）的座標是看截圖估的：建置後轉成圖片確認紅框、色塊有對準，
並在回報中提醒使用者可能需要微調。

每個 `⚠` 警告都要處理（縮短文字、拆頁或補圖）；只有「缺圖」可以保留，但要在回報中列出。
轉成圖片逐頁檢查：文字溢出、導覽列反白是否正確、問題與解法是否一一對應、概念色是否前後一致。
**有問題就修改 deck.json 後重新建置**，不要直接改 .pptx。

## 5. 保持可編輯

使用者會自己修改簡報，所以：
- 文字一律放在文字方塊，不要轉成圖片；架構圖用原生方塊與箭頭繪製，不要用截圖。
- 同一張圖的元件要**組成群組並命名**（例如 `架構圖/Transformer`），方便整組移動或個別修改。
- 缺少的圖用虛線佔位框，框內寫圖號，替換時一眼就知道要放哪張圖。
- 講者備註放完整說明，使用者刪減投影片上的文字後，內容仍然保留在備註裡。

## 6. 回報

交付順序：標注檔（若有）→ .pptx → deck.json。回報內容保持簡短。

**有產生簡報時，一定要附上色彩與概念對照表**，讓使用者修改時能沿用同一套配色。
建置時會印出「色彩對照」表（紅、綠與各概念色的色碼、代表內容、頁碼），直接貼上，
再視需要補上下表中渲染器沒列出的列（例如導覽列的藍色）：

| 顏色 | 色碼 | 代表 | 出現在 |
|---|---|---|---|
| 藍（實心） | `1085DE` | 目前章節、中性標籤 | 導覽列、標籤 |
| 紅 | `E06666` | 問題：〈列出本份的各個問題〉 | 第 x–y 頁 |
| 綠 | `8CD96A` | 解法：〈列出對應的各個解法〉 | 第 x–y 頁 |
| 概念色 1 | `B6CFF5` | 〈概念名稱〉 | 第 x–y 頁 |
| 概念色 2 | `FFECB3` | 〈概念名稱〉 | 第 x–y 頁 |
| 綠色描邊 | `6AA84F` | 架構圖中本頁新增或有變化的元件 | 第 x–y 頁 |
| 紅框 | `FF0000` | 截圖上的重點 | 第 x–y 頁 |

只列出這份簡報實際用到的顏色，並寫出具體的概念名稱，不要寫成通用說明。

表格後面再列出：
- 頁數、導覽列樣式、密度、故事線（各章節或子章節名稱）
- 待填數值與待補圖片（附頁碼與圖號）
- 需要使用者確認的內容
- 一句話說明怎麼切換：「想換單排／雙排或其他密度，跟我說一聲就好。」
